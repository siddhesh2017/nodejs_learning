## Current project technical state

### package.json highlights
- "type": "module"
- Scripts:
  - dev: node --env-file=.env --import=tsx src/index.ts
  - build: tsc
  - start: node --env-file=.env dist/index.js
  - typecheck: tsc --noEmit

### Current CLI behavior (src/index.ts)
- Reads APP_NAME from env.
- Reads userName from argv[2], defaults to Anonymous.
- Reads filePath from argv[3], defaults to data/customers.json.
- Uses node:fs/promises operations:
  - readFile (read input)
  - writeFile (create summary file)
  - appendFile (update log file)
  - unlink (delete temp file)
  - mkdir (create reports directory if missing)
- Uses node:path resolve for normalized input and output paths.
- Uses node:crypto SHA-256 checksum for file-content fingerprint.
- Uses node:events EventEmitter for stage notifications:
  - processing:start
  - processing:fileRead
  - processing:parsed
  - processing:fileWritten
  - processing:fileUpdated
  - processing:fileDeleted
  - processing:error
- Error path sets process.exitCode = 1.

### Day 2 raw HTTP server state
- `src/http-basic-server.ts` exists and runs with `npm run http:dev`.
- Uses `node:http` and `node:url` with manual method/path routing.
- Routes practiced:
  - `GET /health`
  - `GET /hello?name=...`
  - `GET /cpu-logs?spec=memory`
  - `GET /cpu-logs?spec=cpu`
  - `GET /customers`
  - `GET /customers/:id`
  - `POST /customers`
  - `PATCH /customers/:id`
  - `DELETE /customers/:id`
- Customer data is currently an in-memory array matching `data/customers.json`.
- Customer changes reset when the server restarts; persistence was intentionally
  deferred to keep the HTTP lessons simple.
- Request bodies are read manually through the request stream using `data` and
  `end` events, then combined with `Buffer.concat` and parsed with `JSON.parse`.
- The user specifically prefers theory and line-by-line reasoning before each
  small coding exercise. Do not paste a complete large solution without first
  explaining the concept.
